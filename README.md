# StoryBoardStudio

> Excel 驱动的影视分镜 / 资产表可视化工作台。
> Python + Gradio + FastAPI，在浏览器里直接看分镜、图片、音频、视频，改完一键写回 Excel 源文件。

界面分两个 Tab：

| Tab | 内容 | 数据源 |
| --- | --- | --- |
| **📊 表格 A · 影视资产表** | X（人物）/ Y（场景）/ Z（道具）三个 sheet，含提示词、参考音频、声音特质、台词；右端固定「图片预览 / 声音预览」两列，单元格可直接编辑 | `path_a` 指向的资产 Excel |
| **🎬 表格 B · 分镜表** | A–G 列分镜，按镜头号自动匹配音频 / 图片 / 视频，小窗悬停播放、灯箱放大 | `path_b` 指向的分镜 Excel |

## ✨ 核心特性

- 📊 **Excel 原生驱动**：直接读写 `.xlsx`，多 Sheet 切换，sheet 顺序严格按源文件，不做排序
- 🖼️ **图片资产预览**：按编码精确匹配，表格 A 的缩略图逐行对齐行高、可点开灯箱
- 🔊 **音频资产预览**：多轨编码匹配，内置播放器；预览列宽度恒定，不随整表缩放而挤掉进度条
- 🎬 **视频资产预览**：按镜头号自动匹配（`mp4 / mov / webm / mkv`）
- 🎛️ **精细视图控制**：栏宽 / 行高缩放、适配宽度、布局记忆（存 localStorage）
- 📝 **提示词大字区**：点行在上方大字看整行文本
- 💾 **一键写回**：保存前自动备份原 Excel，写坏了大不了回滚
- 🌙 **深色沉浸主题**

## 💻 环境要求

- **操作系统**：macOS（Intel / Apple Silicon 都行）、Windows 10+、Linux
  - 脚本按平台成对提供：
    - 🍎 macOS：`init.command`（**首次克隆后跑一次**）、`launch_sbs_mac.command`、`update-sbs.command`、`push-sbs.command`
    - 🪟 Windows：`launch_sbs_win.bat`、`update-sbs_win.bat`、`push-sbs_win.bat`
    - 🐧 Linux：直接用「手动启动」的命令
- **Python 3.10+**（开发验证于 3.13）
  - Windows 安装时**务必勾选 `Add Python to PATH`**，否则脚本找不到 `python`
- **浏览器**：**Safari 优先**（已针对 WebKit 的 sticky、Shift 组合键差异做过适配），Chrome / Edge 兼容
- **网络**：默认走**官方 PyPI 源**，无需任何额外配置；如果官方源拉得慢，按下方「依赖装太慢」一节临时换镜像即可

## 🚀 安装与首次运行

### 🍎 macOS

#### 0. 第一次先跑一次 `init.command`（**推荐**）

双击 **`init.command`** 就够了，它会一次性做完下面几件事：

- 给目录下所有 `*.command` / `*.sh` 补回**可执行权限**
- 清掉 **`com.apple.quarantine` 隔离属性**
- 顺带体检：哪个脚本被转成了 Windows 的 CRLF 换行会一并提醒（CRLF 会报 `bad interpreter ... ^M`）

**Mac 为什么多这一步**：从 zip 解压、网盘下载或跨盘 / 跨机器拷贝过来的文件，会被 macOS 打上**隔离属性**，同时脚本的**可执行位**常常跟着丢。两种情况的表现不一样：

| 症状 | 原因 |
| --- | --- |
| 双击报「无法打开，因为来自身份不明的开发者」 | 隔离属性没清（Gatekeeper 拦截） |
| 双击**完全没反应**，一点提示都没有 | 可执行位丢了 |

不想双击也可以在终端跑：

```bash
cd /path/to/StoryBoardStudio
chmod +x init.command     # 万一它自己也没权限
./init.command
```

手动版（等价命令，排查问题时更好用）：

```bash
cd /path/to/StoryBoardStudio

# ① 解除隔离属性（递归处理整个目录）
xattr -dr com.apple.quarantine .

#    只处理单个文件也行：
#    xattr -d com.apple.quarantine launch_sbs_mac.command
#    查看某个文件当前有没有隔离属性（没输出 = 干净）：
#    xattr -l launch_sbs_mac.command

# ② 恢复可执行权限（所有 .command 脚本）
chmod +x *.command

#    确认权限已生效：输出里要能看到 x
ls -l *.command
```

> `git clone` 拉下来的通常**不带**隔离属性，但 `chmod +x` 仍建议跑一遍 —— 从别的磁盘 / 网盘拷贝过来时会丢权限位。
> **Windows 不需要这一步**：隔离属性和 Unix 可执行位都是 macOS 独有的东西，`.bat` 没有这两样。
> 更新器（`update-sbs.command`）每次切完版本也会自动重做这两件事，所以一般只有第一次需要记着。

#### 1. 一键启动

双击 **`launch_sbs_mac.command`**：自动创建虚拟环境 → 安装依赖 → 启动服务 → 打开浏览器。
访问地址：<http://localhost:7861>

脚本会先自检端口 7861：**已经在运行就不会重复启动**，只帮你打开页面（重复启动会报 `[Errno 48] address already in use`，看着吓人其实只是「已经开着呢」）。

#### 2. 手动启动（等价命令）

```bash
cd /path/to/StoryBoardStudio
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python StoryBoardStudio.py
```

停止服务：在运行窗口按 `Ctrl+C`。
强杀残留进程：`pkill -f "StoryBoardStu[d]io.py"`（别写 `pkill -f StoryBoardStudio.py` —— 你自己的命令行里也含这个字符串，会连当前 shell 一起杀掉）。

### 🪟 Windows

#### 1. 一键启动

双击 **`launch_sbs_win.bat`**：自动创建虚拟环境 → 安装依赖 → 启动服务 → 打开浏览器。
访问地址：<http://localhost:7861>

脚本同样会自检 7861 端口，**已经在跑就不会重复启动**，只帮你打开页面。

#### 2. 手动启动（等价命令）

```bat

```

停止服务：在运行窗口按 `Ctrl+C`。

### 🔁 依赖装太慢？国内镜像怎么切

**默认走官方 PyPI 源**（`https://pypi.org/simple`），不需要改任何文件、也不需要额外配置。

国内网络要长期加速时，仓库里**已经备好一份镜像版清单**，改个名就生效，**启动脚本一行都不用动**：

```bash
cd /path/to/StoryBoardStudio

# ①（可选）先把官方版留个底，方便随时换回来
mv requirements.txt requirements_官方源.txt.bak

# ② 镜像版顶上，改完就能直接用启动脚本了
mv requirement_国内源.txt requirements.txt
```

两个文件依赖完全一致，`requirement_国内源.txt` 只多一行：

```
--index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

想换回官方源：

```bash
git checkout requirements.txt                                    # 有 git 就直接还原
mv requirements_官方源.txt.bak requirements.txt                   # 或者把刚才的备份改回来
```

> 只是临时跑一次、不想动文件也行：`pip install -r requirements.txt -i <镜像地址>`
>
> ⚠️ **平时别把 `--index-url` 留在 `requirements.txt` 里** —— 一旦那个源不通，整个安装会卡死在那儿，还不好排查（这正是当初踩的坑）。所以放在单独一份文件里按需切换，而不是默认写死。

### ⚠️ venv 不要跨机器拷贝（重要）

`venv/` **不进仓库**（已被 `.gitignore` 屏蔽），每台机器首次运行时由启动脚本自动创建。

千万别把一台机器上的 `venv/` 整包拷到另一台机器，**跨操作系统更是 100% 用不了**：

| 拷贝场景 | 结果 |
| --- | --- |
| 同一台机器原地保留 | ✅ 正常 |
| 另一台 Apple Silicon Mac（用户目录/路径不同） | ❌ venv 里脚本的 shebang 写死了绝对路径，直接失效 |
| Intel Mac | ❌ site-packages 里装的是 arm64 二进制 |
| Windows / Linux | ❌ Mac 上是 Mach-O `.so`；Windows 要 `.dll` / `.pyd`，且目录结构是 `Scripts\` 而非 `bin/` |

三个启动脚本都会**自动识别「有 venv 但不可用」**的情况（检测 `venv/bin/python` 或 `venv\Scripts\python.exe` 是否存在），改名留档为 `venv_broken_*` 后重建，一般不用你操心。想手动清理就整个删掉 `venv/` 再启动一次。

`asset_tab.py` 是**必需文件**，缺了主程序起不来（ImportError）。
在 `StoryBoardStudio.py` 里加功能时，**新逻辑请写进独立模块**（照 `asset_tab.py` 的样子：自带 CSS/JS/索引/接口，类名统一加前缀），主程序只保留 import + 挂载那几行，避免两部分的代码互相污染。

### 配置文件 `gradio_temp/config.json`

```json
{
  "path_a": "资产表 .xlsx 的绝对路径",
  "path_b": "分镜表 .xlsx 的绝对路径",
  "asset_dir": "素材根目录",
  "audio_dir": "资产音频目录（A 表 X/Y/Z 试听用；留空 → 资产目录/Audio → 资产目录）",
  "audio_b_dir": "模式2 成品音频目录（B 表 C 列匹配用；留空 → 资产目录，递归子目录）",
  "video_dir": "视频目录（留空 → 同资产目录）",
  "b_mode": "ref2v / digital_human"
}
```

**两个音频框不是一回事**，别混：

| 框 | 服务对象 | 里面通常放什么 |
|---|---|---|
| 资产音频 | 表格 A（X/Y/Z 行） | `X01.何功伟旁白.flac`、`Y03.审讯室.wav`——**角色/场景样音** |
| 模式2 音频 | 表格 B（C 列） | `s001-01.wav`、`s010-03.flac`——**footage 成品音轨，文件名就是镜头号** |

「模式2 音频」留空时，直接拿**资产目录**做根，`os.walk` 逐层遍历（`资产/Audio/…`、
`资产/2026-11-02/batch1/…` 都认）。**刻意不去猜「资产目录/Audio」这种子目录**——
猜错一次就是满屏「未配音」，而递归找本来就不需要猜。
它也不会去读「资产音频」那个框：把 `X01.wav` 当成 footage 音轨只会让 C 列更糊涂。

界面上改完路径**失焦（点别处）就会自动写回**这个文件，不需要手改，也不必等点「🚀 加载/刷新工程」。

**刷新或重开网页时，顶部那 6 个路径框 + B表模式下拉会自动回填上一次的值**，不用每次重敲：

- 打开 / 刷新页面 → 从 `config.json` 把路径读回输入框
- 手打、粘贴、以及点「📁」选出来的路径 → 立即落盘（失焦或内容变化时）
- 内容跟文件里一致时不会重复写盘，所以 `config.json` 的修改时间只会因为你真的改了路径而变

**六个路径框右侧都有一个 📁 按钮**（表格 A / 表格 B → 选文件；模式2 音频 / 资产目录 / 资产音频 / 视频目录 → 选文件夹）。
点一下由**服务端**弹系统原生选择框，选完整条路径回填到框里：

| 系统 | 用的什么 | 备注 |
|---|---|---|
| macOS | `osascript` 的 `choose folder` / `choose file` | 对话框可能出现在浏览器窗口后面，看一眼 Dock |
| Windows | PowerShell + `System.Windows.Forms` 的 Folder/FileBrowserDialog | 用 `CREATE_NO_WINDOW` 起，不闪黑框；中文路径按 UTF-8 回读 |
| Linux | `zenity --file-selection` | 没装 zenity 会提示手动粘贴 |

取消选择不会覆盖原值；按钮挂在输入框右端（绝对定位），**不占纵向空间**。
锚点是每个框的 `elem_id`（`sbs-path-*`），不是 label 文字——改标签名不会再让按钮悄悄消失。

> `gradio_temp/` 属于**运行时目录，已被 `.gitignore` 忽略**（`config.json` 里是本机路径，属于个人环境信息，不该进仓库）。所以换台机器克隆下来后，第一次打开是空的，填一次就记住了。

### ✅ 该提交进仓库的 / ❌ 不该提交的

**该提交**：`StoryBoardStudio.py`、`asset_tab.py`、`requirements.txt`、`requirement_国内源.txt`、`README.md`、`.gitignore`、四个 `.command` 脚本（macOS，含 `init.command`）、三个 `_win.bat` 脚本（Windows）

**不该提交**（已被 `.gitignore` 屏蔽）：

```
__pycache__/                     # Python 字节码缓存，删了会自动重建
*.pyc  *.pyc.*                   # py_compile 失败时留下的临时字节码
_backups/                        # 代码快照 + Excel 备份回退目录
gradio_temp/                     # 运行时目录：config.json 存的是本机 6 个路径 + 模式（个人环境信息）
.DS_Store                        # macOS 目录元数据
venv/                            # 虚拟环境（首次运行本机自动创建）
```

> `.DS_Store` 已通过 `git rm --cached .DS_Store` **退出跟踪**，不会再被提交。
> 如果你在别的机器上还有旧克隆，那台机器要自己跑一次 `git rm --cached .DS_Store` 才能同步。
>
> `gradio_temp/config.json` 同样已 **`git rm --cached` 退出跟踪**（它存的是「你这台机器的路径」，
> 进仓库既会泄露本地目录结构，也会让别人克隆下来看到你的路径）。如果你有旧克隆，
> 那台机器也跑一次 `git rm --cached gradio_temp/config.json`；不跑也不影响使用，只是 `git status` 里会多一条删除。

## ⌨️ 快捷键

键盘上 `a s d f g h` 连成一排，手指不用挪窝。**焦点在输入框 / 下拉框里时不生效**（正常打字优先）。

| 按键 | 作用 |
| --- | --- |
| `a` / `s` | **当前这张表内切 sheet** —— 表格 A 走「◀ 上一表 / 下一表 ▶」，表格 B 走「上一场 / 下一场」 |
| `d` / `f` | **切 Tab 页面**：`d` → 表格 A，`f` → 表格 B |
| `g` / `h` | 横向缩放（整表栏宽）：`g` 收窄，`h` 拉宽 |
| `Shift` + `g` / `h` | 纵向缩放（行高）：`Shift+g` 收紧，`Shift+h` 拉开 |
| `r` | 恢复默认排版（对当前所在的 Tab 生效） |
| `Shift` + 滚轮 | 表格横向滚动（**普通鼠标唯一的横向手段**，触控板也可两指横划） |

> **鼠标 vs 触控板**：触控板能两指左右划，普通鼠标只有一个纵向滚轮，所以约定
> **`Shift` + 滚轮 = 横向滚动**（和 Excel、浏览器一致，不占用任何系统快捷键）。
> 不按 `Shift` 时纵向滚动照旧，不会被拦。
>
> 横向滚动条平时**隐形**（滑轨与滑块全透明，绝不白吃高度）；鼠标移进表格区域才浮出来，
> 想精确拖动时随时点得到。

> **跨平台差异（实测，Chrome 156 / headless 两种模式）**：同样这套 CSS，两个平台表现不同，
> 因为操作系统底层的滚动条机制不一样。
>
> | 平台 | 滚动条机制 | 实际占位 | 自动隐藏 | 悬停显形 |
> |---|---|---|---|---|
> | macOS（Chrome / Edge） | overlay，浮在内容上 | **0 px** | ✅ | ✅ |
> | Windows（Edge / Chrome） | classic，挤压内容区 | 约 **11 px** | ✅ | ✅ |
>
> 原因是浏览器对 `scrollbar-width: thin` 的实现：macOS 走 overlay 分支不占位，
> Windows 走占位分支要吃掉 11px（不做这个处理的话默认是 15px、而且永远可见）。
> 视觉上两个平台都是"平时看不见、靠近才出现"，差别只在 **Windows 上表格宽度少 11px**。
>
> **不影响使用**：横向滑动两个平台都靠 `Shift` + 滚轮，PC 上不需要去够那条滚动条；
> 真要精确拖动时，鼠标移进表格它自己就浮出来了。
> 滚轮事件在 Windows 的 Firefox 里是"行"模式（`deltaMode === 1`，一次只有 ±3），
> 代码已统一折算成像素，手感与 macOS 一致。

## 📖 功能说明

### 表格 A · 影视资产表

- 列头带 **Excel 真实列号前缀**：`A.资产编号`、`B.资产名称`、`C.文生图 / 图生图提示词`……
- 最右侧 **📷 图片预览 / 🔊 声音预览两列吸附在视口右边**，横向滚动时始终可见；这两列宽度恒定，**不参与整表缩放**

**两种生成模式（统一口径：模式1 = 全参考，模式2 = 数字人）**

| | **模式 1 · 全参考（Ref2V）** | **模式 2 · 数字人** |
| --- | --- | --- |
| C 列填 | **数字时长**：`4` / `5.5` / `8s` / `132f` | **镜头号**：`s001-01`，SBS 据此匹配同名音频 |
| 管线 | 图片（≤6）+ 音频（≤3）一次性进参考生成节点，音画同出 | 先 TTS 出成品音频 → 音频驱动唇形生成视频，时长 = 音频长度 |
| 空镜 | 直接填时长 | 用等长**无声 mp3 占位**，视频按占位长度生成 |
| 擅长 | 多人、走位、动作、画外音、旁白、空镜 | 单人正脸中近特对白（唇形最准，几乎一次过） |
| 不擅长 | 唇形只能靠提示词描述 | 不能走位、不能多人、不能大幅动作 |

**C 列是双语义列，语义由页面顶部「表格 B (分镜表)」路径框右侧的模式下拉决定**
（两项：**模式1 全参考** / **模式2 数字人（声音驱动）**，选择存在 `gradio_temp/config.json` 的 `b_mode`）：

- **模式1 全参考** → C 列一律当**时长**，只显示数字本身，**不去音频目录找任何东西**；
  `f` / `s` 只是标记，SBS 做展示不做换算
- **模式2 数字人** → C 列一律当**音频线索**，去「模式2 音频」目录（含子目录）找同号文件，
  `mp3` / `wav` / `flac` / `m4a` / `aac` 都认，`<audio src>` 直接指向该文件的绝对路径
  （`/api/local_media?filepath=...`），找不到就显示灰色「未配音」方块
- **点「🚀 加载/刷新工程」时按文件内容自动认一次**（抽 C 列前 60 个非空值：数字多→模式1，
  镜头号多→模式2），并把下拉拉到位；加载完照样可以手动切。
  **模式不重复显示在表格上方**——那是顶部下拉的职责，表格区只报数

模式2 的搜索根（顶部「模式2 音频」框）：

| 该框 | 搜索根 |
|---|---|
| 填了 | 就用它，`os.walk` 递归整棵子树 |
| 留空 | **资产目录**，同样递归（`资产/Audio/x.wav`、`资产/2026-11-02/batch1/x.wav` 都命中） |

表顶那行「音频：/某/路径（模式2 音频 / 资产目录兜底，含子目录）」就是当前实际搜索根——
未配音一排的时候先看这一行，多半是路径指错了，不是文件没生成。

模式2 的匹配规则：

| C 列内容 | 行为 |
|---|---|
| 空 / `n/a` / `-` | 用 A 列镜头号去找 |
| `s001-01` | 直接用（最常见） |
| `s001-01.mp3` | **指定这个容器**，即使同号有 wav 也用它 |

- 同号多容器按 **wav > flac > mp3 > m4a > aac** 取一个，结果确定，不随 `os.walk` 顺序变
- 界面 badge 显示容器名（`WAV` / `MP3` / `FLAC`），悬停看完整文件名
- 同名精确优先；没有同名才退到前缀近似（`s001-01.何功伟的话.mp3`），近似命中 badge 前带 `≈`
- 前缀匹配的分隔符只有 `.` `-` `_` 空格，所以 `s001-01a.mp3` 不会被 `s001-01` 误匹配——副镜头天然安全
- 表顶显示 `本场 N 镜 · 已配音 x / 未配音 y`，扫一眼就知道还差多少

### 视图操作

**两个 Tab 各有一排「📐 视图微调」**：`◀ 栏宽收窄` / `▶ 栏宽拉宽` / `▲ 行高收紧` / `▼ 行高拉开` / `↔ 适配宽度` / `📌 记住排版`（写入 localStorage）/ `🔄 恢复默认`。表格 B 另有「✓ 隐藏/显示列」，可单独藏掉某几列。

- **横向缩放**改栏宽（整表所有列）；**纵向缩放**改行高
- 表格 B 的行高由 **B 列小标题 / D 列台词 / F 列提示词 / G 列视频占位**四个框决定，纵向缩放会一起改；**E 列图片、G 列视频画面跟「栏宽」走，不跟行高**，这样拉高一行只是多出空白，媒体不会被拉变形
- 表格 A 右端 **📷 图片预览 / 🔊 声音预览两列宽度恒定**，横向滚动时吸附在视口右边，**不参与整表缩放**
- 那几个文本框可以手动往下拖高；拖过之后它会被内联高度锁住，此时按 `Shift+g` / `Shift+h` 或 `r`，内联高度会被清掉、重新交回缩放接管

#### 纵向空间怎么分的（改布局前先读这段）

表格上方四条横带，占的全是表格本体的高度，所以都按「能一行就一行」压过：

| 横带 | 高度 | 怎么压的 |
|---|---|---|
| 顶部路径行 | 71px | 六个框 + B表模式下拉挤在一行（`flex-wrap:nowrap`，min-width 归零）；B表模式下拉**定宽 104px**，只够「模式1 全参考」六个字 |
| 场次工具栏 | 81px | 「隐藏/显示列」七个复选框从 35px/个 的方块压成 17px 的窄标签，一行放得下（窗口 <1200 时才折两行） |
| 视图微调行 | 32px | 行首「📐 视图微调」不是组件，是 CSS `::before`；按钮 24px 高 |
| 提示词预览行 | 110px | **不动**（90px 的预览框是常用观察区，用户明确要求保留） |
| 冲突提示 | 0px | 没冲突时连外层壳一起 `display:none`（`:has(:empty)`），不再白留 20px |

**表格视口 `max-height` 锁死 72vh，不要改成 `calc(100vh - Xpx)`**——那会按窗口把表格本体削掉（实测从 648px 掉到 424px），省出来的高度应该给表格，不是给留白。

## ⚠️ 注意事项 / 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 双击 `.command` 打不开，提示「身份不明的开发者」 | 隔离属性没解除：`xattr -dr com.apple.quarantine .`（见「安装」第 0 步） |
| 双击 `.command` 一闪而过 / Permission denied | 缺可执行位：`chmod +x *.command` |
| 终端报 `[Errno 48] address already in use` | 7861 已被占用，说明服务本来就在跑 → 直接开 <http://localhost:7861>；要重启先在原窗口 `Ctrl+C` |
| 改了代码但页面没变 | 老实例还占着端口，新进程没起来 → `lsof -nP -iTCP:7861 -sTCP:LISTEN` 确认后重启 |
| 保存报「文件正在被占用」 | 用 Excel / WPS 打开着同一个文件，关掉再保存 |
| 图片 / 音频显示「无文件」 | 素材命名不符合上面的硬规则，页面顶部红字会给出建议改名（**不会自动改名**） |
| Safari 下 `Shift` 组合键不灵 | 已按 `e.shiftKey` 判定；若仍异常请确认 Safari 升级到较新版本 |
| **Win**：表格右侧多出一条约 11px 的空白带 | 不是 bug：Windows 的滚动条是**占位式**的（macOS 悬浮在内容上，所以是 0px）。平时透明、鼠标靠近才浮出；横向滑动用 `Shift` + 滚轮，不影响使用 |
| **Win**：`.bat` 双击一闪而过 | 先在 `cmd` 里手动跑一遍看报错；多为没勾 `Add Python to PATH`，或公司策略禁止脚本执行 |
| **Win**：提示 `python` 不是内部或外部命令 | Python 没加进 PATH → 重装时勾选 `Add Python to PATH`，或改用 `py -3` 代替 `python` |
| **Win**：`.bat` 中文提示乱码 | 脚本已 `chcp 65001`；老 `cmd` 字体不全时换 Windows Terminal |
| **Win**：`netstat` / `taskkill` 提示拒绝访问 | 用「以管理员身份运行」重开终端 |
| `pip` 卡住不动 | 默认走官方源；国内网络慢就按「依赖装太慢」一节把 `requirement_国内源.txt` 改名为 `requirements.txt`；公司 / 校园网代理需另配 `set HTTPS_PROXY=...`（Win）或 `export HTTPS_PROXY=...`（macOS） |
| 从 Mac 拷 `venv` 到 Windows，启动报错 | venv **不能跨系统**，删掉整个 `venv/` 目录后重新双击启动脚本（见「venv 不要跨机器拷贝」） |

## 🔄 更新与推送

**macOS**

```bash
./init.command          # 🍎 首次克隆后跑一次：补权限 + 解隔离（Mac 专用，Windows 不需要）
./update-sbs.command    # 交互式更新（见下方说明）
./push-sbs.command      # 提交并推送（工作区干净时会直接退出，不会产生空提交）
```

**Windows**：直接双击 `update-sbs_win.bat` / `push-sbs_win.bat`（或在 `cmd` 里运行同样名字）。

### 更新器怎么用

两个平台的更新脚本都是薄壳，真正的交互逻辑在 `sbs_update.py` 里（Mac / Win 行为完全一致，也不会被 `cmd.exe` 的中文乱码问题波及）：

1. 先连远程仓库，**SSH 可用就用 SSH，不可用自动回退 HTTPS**，并顺手把 origin 地址纠正过来（换机器不用改配置）；
2. 列出远程最近 **20 条提交**，每条带短 SHA、日期时间、作者、说明，并标出「← 本地当前」；
   **本地已经是最新时也会列出菜单**，方便你回退到历史版本，直接按 `q` 退出即可什么都不做；
3. 输入序号 `1`–`20` 选择要部署到本地的版本，**直接回车 = 1（最新版）**，输入 `q` 取消；输入别的会提示重新输入，不会退出；
4. **优先安全推进**：所选版本在本地历史前方 → `merge --ff-only` 快进，不碰你的分支历史；
   只有明确要回退或横向切换时才 `reset --hard`，且会先警告并要求你确认，不会闷头冲掉本地提交；
5. 切换前若工作区有未提交改动，会自动 `git stash` 留档，并在结束时打印 `git stash pop` 的取回方法；
6. 本地存在「不在远程上的提交」时会额外确认一次（`reset --hard` 不删数据，它们仍在 `git reflog` 里）；
7. 切完会打印**本次变动的文件清单**（新增 `A` / 修改 `M` / 删除 `D` 一目了然）；
8. 切换后自动给 `.command` 补权限 + 清隔离属性（等于帮你跑了一次 `init.command`），然后询问是否更新依赖，可选 `requirement_国内源.txt` 走国内镜像；
9. 万一选中的是还没有这些脚本的早期版本，脚本会把运行器本体写回磁盘，不会让你失去启动 / 更新 / 推送入口。

脚本只移动 git 指针，**不删任何文件**。想回到最新版：再跑一次，直接回车即可。

推送同样走上面的自动通道：默认 SSH（`git@github.com:gnrsbassoutlook/StoryBoardStudio.git`）需要本机已配置 GitHub SSH 密钥，但**没配密钥也不用管**，会自动回退 HTTPS。推送前还会先 `fetch` 比对，本地落后时先 `--rebase --autostash` 再推，从根上减少冲突。
